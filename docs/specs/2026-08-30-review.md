# 复盘回放设计文档

> 目标：点开一条复盘 = 结束页原样（左对话右报告，两栏各自滚动）。展示不重写、不摘要、不重排。
>
> **本文件是第 6 步骨架。产品第 5/6 步未上线。** 不改前端与路由，只定只读契约与纯函数入口。

## 背景

结束瞬间的权威数据是 `reviews.snapshot_json`，不是当场再跑一遍 Agent。产品理念：「全文原样进复盘；点开复盘 = 结束页，展示不重写。」若复盘去调用报告生成函数，学生会看到被事后润色的对话或另一份总评，诊断失效。

本骨架只提供 `load_review_for_replay` 与列表预览派生。列表可以截陈述前 40 字；详情必须用 snapshot 全文。

## 只读原则

1. 复盘的唯一输入是已落库的 `snapshot_json`（及同行的 `report_text`，二者必须一致）。
2. 允许：`json` 反序列化、`ReviewSnapshot` 校验、派生 `statement_preview`。
3. **禁止**：`build_report_from_parts`、`compose_report_text`、`assemble_review_snapshot`、`dump_end_snapshot`、`build_end_report_context`、未来的 `write_report` / MiniMax。
4. **禁止**：UPDATE `reviews`；禁止按当前 `sessions`/`turns` 重建 snapshot（结束之后 turns 不应再变，但复盘仍不得回源重写）。
5. `GET /api/reviews/{id}` 的 HTTP body 必须是列里的原始 `snapshot_json` 字符串，不要 loads 后再 dumps。

## 数据从哪来

结束页与复盘页共用同一 JSON：

- `session`：方向列表、陈述全文、岗位、首问
- `turns`：按 `seq` 的面试官 / 用户 / 思考原文（思考含 tool 过程）
- `report.text`：四段报告全文

字段定义见 [2026-08-30-report.md](./2026-08-30-report.md)。列表不另存陈述副本，避免和 snapshot 漂移。

## 日后 API（本骨架不实现）

| 端点 | 鉴权 | 说明 |
| --- | --- | --- |
| `GET /api/reviews` | 匿名 | `[{ id, created_at, statement_preview, role }]`，`created_at` 降序 |
| `GET /api/reviews/{id}` | 匿名 | 200：原始 `snapshot_json`；404：无此条 |

`list_reviews()` 已按「解析 stored JSON → 截前 40 字」实现，不写回数据库。

刷新浏览器后列表仍在，因为数据在 SQLite，不在内存。

## 前端（第 6 步才做）

- 左入口「面试复盘」：`list-item` = 时间 + 岗位 + 陈述前 40 字。
- 点开调用与结束页同一 `renderEndedView(snapshot)`。
- 两栏 `overflow:auto` 各自滚动；中间 1px divider。
- 禁止前端改写字段、重排 turns、把报告摘要进对话。
- 空列表走 `empty-state`。

本骨架不改 `static/`。

## 与第 3 步 / 第 5 步的边界

- 第 3 步：`status=live` 的问答。复盘模块不读取进行中的 session 来「预生成」报告。
- 第 5 步：`/end` 第一次写入 reviews。复盘只消费这一次写入。
- 接线时 `main.py` 增加两个 GET 即可，不要在 GET 里调 `agent.py`。

## 单测约定

`tests/test_report_snapshot.py` 只测纯函数：

- snapshot 含 session + 全部 turns.body + 报告原文，不省略
- `load_review_for_replay` 期间若触发任何生成/组装函数则失败
- 回放后的 statement / turn.body / report.text 与冻结值一致

不在本步做浏览器复盘验收。

## 反模式

- 不把复盘做成「再面一次」或「用新 prompt 重写总评」
- 不把当前 `sessions.status` 仍为 `live` 的场次列进复盘
- 不在复盘详情里隐藏 thought
- 不改第 3 步文件、不重启、不公网点复盘页冒充第 6 步完成
