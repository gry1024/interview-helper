# 面试深度与报告区分度

> 目标：一场面试沿已定方向下钻足够多轮；结束报告能分开优秀学生和较差学生；较差场必须真正查到代码并证伪吹嘘。

## 背景

公网已结束场次多为 2～3 轮用户回答就点结束，且样本几乎全是「用了 RoPE / 不太懂 / 吹 rerank」。前端从开场就允许点「结束面试」，验收脚本也常在第 3 轮停。模型一侧则把一句「不懂」或一句像样的完整回答当成 `direction_done=true`。

本步只改话题锁、结束条件、报告定档和验收脚本，不改 `static/`、JD 库、`code_inspect` 沙箱。

## 产品规则

1. 用户随时可以自己点结束，系统不禁用结束按钮。
2. 模型不得在 `next_question` 里劝结束。
3. 同一方向默认 6～10 轮。未满 4 轮学生回答，或 goal 检查点未覆盖，不得 `direction_done=true`。
4. 第一次「不懂」必须换说法再问；换说法后仍空白才可记挖不动。
5. 答得差也不跳方向，不发明新方向。
6. 回答出现 rerank / 万卡 时，即使模型没 call tool，服务端也补一次 `code_inspect`。
7. 报告总评第一句必须是唯一 `整场主档：` 四档之一。
   - 优秀：真懂 / 懂但讲不出
   - 较差：真不懂 / 项目里没有
   - 两场主档必须不同，禁止都落「懂但讲不出」

## 公网验收

标准样本：岗位 `llm-algo`，仓库 `https://github.com/jingyaogong/minimind.git`，陈述用开发计划 §1 MiniMind 原文。

```bash
python3 docs/specs/accept_public_depth.py
```

脚本必须：

1. 打开 `http://120.26.176.60`，用 Playwright 真实点击，不用 Cursor browser MCP。
2. 优秀场：6 轮具体、正确、贴 MiniMind 的回答，不吹假能力。
3. 较差场：前几轮含糊/不太懂，必须有一轮明确吹 rerank + 万卡；思考区出现 `查代码：是` 且结论证伪；下一问无文件名行号。
4. 每场至少 6 轮回答再点结束。不要在第 3 轮停。
5. 结束后打开复盘，两场都在，且 `整场主档` 不同。
6. 证据写入 `docs/specs/accept_public_depth_last.json`。

## 反模式

- 不改前端禁用结束按钮
- 不另起抢 80 端口的 uvicorn
- 不覆盖同事正在改的 `static/`
- 没有「优秀 vs 较差档位不同」和「较差场 code_inspect 证伪」证据，不得声称完成
