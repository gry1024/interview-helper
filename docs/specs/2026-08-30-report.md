# 结束报告与 reviews 落库设计文档

> 目标：用户点结束后，生成含四段处方的报告全文，并在结束瞬间把 session + 全部 turns + 报告原文冻进 `reviews.snapshot_json`。
>
> **本文件是第 5 步骨架。产品第 5/6 步未上线。** 不改 `app/main.py`、`app/agent.py`、`app/db.py`、`static/`，不重启服务，不做公网验收。

## 背景

第 3 步正在接通面中 SSE 与话题锁。面中只展示思考（评价 / 是否查代码 / 本方向是否结束），禁止总评和建议。第 5 步才允许加载 `app/prompts/report.md`，把岗位本质对照、价值和处方写到右侧报告。

本骨架先把 prompt、snapshot 纯函数、reviews 表隔离模块写完，供第 3 步结束后接线。权威约束见 [产品理念.md](../产品理念.md)、[产品功能.md](../产品功能.md)、[开发计划.md](../开发计划.md)。

## 数据库（隔离，尚未并入 db.py）

SQLite 仍是 `data/app.db`。**不要改现有 `app/db.py`。** 建表与读写放在 `app/db_reviews.py`：

```sql
CREATE TABLE IF NOT EXISTS reviews (
    id TEXT PRIMARY KEY,
    session_id TEXT NOT NULL UNIQUE,
    created_at TEXT NOT NULL,
    report_text TEXT NOT NULL,
    snapshot_json TEXT NOT NULL
)
```

| 列 | 含义 |
| --- | --- |
| `id` | 默认同 `session_id` |
| `session_id` | UNIQUE，一场只有一份复盘 |
| `created_at` | UTC ISO |
| `report_text` | 报告全文，不省略 |
| `snapshot_json` | 结束瞬间完整副本，复盘只读这份 |

规则：

- `save_review` 只 INSERT，已存在则抛 `ReviewAlreadyExistsError`，禁止 UPDATE 改写 snapshot。
- `get_review` 返回列的原始字符串，禁止 `json.loads` 后再 `dumps`。
- 写入共用 `app.db._write_lock` 与 `app.db.connect()`，路径仍走被 monkeypatch 的 `DB_PATH`。

### 合并进 `app/db.py` 的补丁提纲（第 5 步接线时再做）

1. 在 `init_db()` 创建 `turns` 之后调用 `init_reviews_table(connection)`，与 sessions/turns 同一次 `commit`。
2. 把 `save_review` / `get_review` / `get_review_by_session` / `list_reviews` 迁入或从 `db_reviews` 再导出。
3. 新增 `mark_session_ended(session_id)`：`UPDATE sessions SET status = 'ended' WHERE id = ?`。与 `save_review` 同一把写锁，**最好同一事务**：先插入 review，再改 status，避免 `ended` 却没有 snapshot。
4. 不要改 `sessions` / `turns` 现有列，不要改 `append_turn_bundle` 语义。
5. 生成后禁止 `UPDATE reviews.snapshot_json` / `report_text`。
6. 合并完成后可删除 `db_reviews.py`，或让它变成薄再导出，避免双份 DDL。

## snapshot 字段

由 `assemble_review_snapshot` / `dump_end_snapshot` 生成，schema_version = 1：

```json
{
  "schema_version": 1,
  "session": {
    "id": "uuid",
    "created_at": "2026-08-30T03:00:00+00:00",
    "github_url": "https://github.com/jingyaogong/minimind.git",
    "statement": "项目陈述全文，不截断",
    "role": "llm-algo",
    "directions": [{"id": "d1", "title": "...", "goal": "..."}],
    "current_direction_id": "d1",
    "clone_path": "repos/uuid 或 null",
    "clone_ok": true,
    "status": "ended",
    "first_question": "开场第一问全文"
  },
  "turns": [
    {
      "id": 1,
      "session_id": "uuid",
      "seq": 0,
      "role": "interviewer",
      "body": "原文，不摘要",
      "direction_id": "d1",
      "meta": null
    }
  ],
  "report": {
    "text": "## 总评\n\n...四段全文..."
  }
}
```

- `session` 取结束瞬间的 `get_session` 字段；snapshot 内 `status` 固定为 `ended`，**不原地改**传入的 session dict。
- `turns` 为 `list_turns` 的全部行（含全部 `thought` 与 tool `meta`），`body` 字节级保留。
- `report.text` 与 `reviews.report_text` 必须是同一份全文。
- 序列化：`ensure_ascii=False`，不截断。HTTP 复盘接口日后必须回传**列里的原始字符串**。

Pydantic：`app/review_models.py` 的 `ReviewSnapshot`。不要改 `app/models.py`。

## 报告生成（纯函数，未接 LLM）

`app/report.py`：

| 函数 | 用途 |
| --- | --- |
| `load_report_prompt` | 读 `app/prompts/report.md` |
| `build_end_report_context` | 把陈述 + 方向 + **全部** turns.body 打成 JSON，供日后 MiniMax |
| `build_report_from_parts` / `compose_report_text` | 拼装或验收四段，原文不省略 |
| `assemble_review_snapshot` / `dump_end_snapshot` | 结束瞬间冻结 |
| `load_review_for_replay` | 复盘只反序列化，禁止走上面的生成函数 |

报告必须含四段标题：`总评`、`岗位本质对照`、`知识建议`、`项目改良`。四档落差（真懂 / 懂但讲不出 / 真不懂 / 项目里没有）只许出现在报告里。

面中思考禁止出现：`建议你`、`总评`、`复习`、`岗位本质对照`、`知识建议`、`项目改良`。`thoughts_leak_report_content` 供日后接线自检。

## 日后 API（本骨架不实现）

| 端点 | 说明 |
| --- | --- |
| `POST /api/sessions/{id}/end` SSE | 无 body。事件：`report_delta` / `tool` / `done` |
| `GET /api/reviews` | `[{ id, created_at, statement_preview, role }]`，preview = 陈述前 40 字 |
| `GET /api/reviews/{id}` | **原样**返回 `snapshot_json` 字符串 |

`/end` 服务端顺序：

1. session 必须是 `ready` / `live`。
2. `get_session` + `list_turns`（现有 `db.py`，不改语义）。
3. 系统提示改用 `report.md` + 岗位本质；**允许** `code_inspect`（评估价值、最小改造）。
4. `compose_report_text` 验收四段。
5. `snapshot_json = dump_end_snapshot(session, turns, report_text)`。
6. `save_review`；同一事务 `status=ended`。
7. 生成后不再改历史 turns。
