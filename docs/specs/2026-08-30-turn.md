# 面中一轮 SSE 与话题锁设计文档

> 目标：用户提交回答后，系统流式输出本轮思考，再给出锁在当前方向内的下一问；思考贴在该答下方，思考结束前禁止发送。

## 背景

第 2 步已完成建会话、固定方向、首问展示和浅克隆。第 3 步补齐核心问答循环；`code_inspect` 完整实现放在第 4 步，本步只预留事件契约，不要求模型实际调用代码 tool。

## 数据库改造

在现有 `sessions` 之外新增 `turns`：

```sql
CREATE TABLE IF NOT EXISTS turns (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id TEXT NOT NULL,
    seq INTEGER NOT NULL,
    role TEXT NOT NULL CHECK (role IN ('interviewer', 'user', 'thought')),
    body TEXT NOT NULL,
    direction_id TEXT,
    meta_json TEXT,
    UNIQUE(session_id, seq)
)
```

建会话成功后立即写入：
- `seq=0` `role=interviewer`：首问原文，`direction_id=d1`
- 可选：不单独落“方向列表”行；方向仍以 `sessions.directions_json` 为准

每轮回答后按序追加：
1. `user`：用户原文
2. `thought`：完整思考原文（含评价、是否查代码、本方向是否结束）
3. `interviewer`：下一问原文

若 `direction_done=true` 且存在下一条方向，更新 `sessions.current_direction_id`。

## API 设计

| 端点 | 方法 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| `/api/sessions/{id}/turns` | POST | 匿名、写限流 | SSE 返回本轮思考与下一问 |

请求：

```json
{ "answer": "用户回答" }
```

约束：
- session 必须存在且 `status` 为 `ready` 或 `live`
- 回答长度 ≤ 8000，去控制字符
- 并发：同一 session 同时只允许一轮进行中（内存锁）

SSE 事件：

| event | data | 时机 |
| --- | --- | --- |
| `thought_delta` | `{ "text": "..." }` | 思考流式片段 |
| `tool` | `{ "name": "code_inspect", "args": {}, "result": "..." }` | 本步可空发；第 4 步启用 |
| `question` | `{ "text": "...", "direction_id": "d1", "direction_done": false }` | 思考结束后 |
| `error` | `{ "message": "..." }` | 失败 |
| `done` | `{}` | 本轮结束 |

## Agent 行为

1. 系统提示顺序：`interviewer.md` → `job_essence.md` → 本场 role/陈述/方向列表/当前方向。
2. 明确：仓库不在上下文；本步默认不查代码，`thought` 中写“查代码：否”。
3. 模型输出 JSON：

```json
{
  "thought": "评价……\n查代码：否……\n本方向结束：是/否，因为……",
  "direction_done": false,
  "next_question": "……"
}
```

4. 话题锁：
   - `direction_done=false` → 下一问必须是当前方向下一步
   - `direction_done=true` → 下一问必须是下一条已定方向第一步；无下一条则收束，不发明新方向
   - 答得差也不跳方向，除非 goal 已无法推进
5. 实现策略：MiniMax 非流式拿完整 JSON，再按句/段伪流式推送 `thought_delta`，最后发 `question` 和 `done`。思考必须完整出现在问题之前。

## 前端设计

- 进行态改为整屏对话：左气泡面试官，右气泡用户，用户气泡正下方 `.thought` 流式填入。
- 底部输入框 + 发送；“结束面试”按钮先占位禁用或仅 UI，不接第 5 步逻辑。
- 开场后已有首问气泡；提交回答后追加用户气泡与思考区。
- 思考进行中禁用发送；结束后左侧新增下一问气泡。
- 过滤思考中任何“建议你 / 总评 / 复习”类段落（前端兜底）。

## 验收标准

- [ ] MiniMind 场次回答后，思考出现在该答下方，下一问在左
- [ ] 连续 3 答仍在同一方向逐步推进
- [ ] 思考未结束时发送无效
- [ ] SSE 响应头含 `text/event-stream`
- [ ] turns 原文落库无截断

## 反模式

- 不实现完整 code_inspect（第 4 步）
- 不实现结束报告与复盘（第 5/6 步）
- 不在面中输出建议或总评
- 不因答得差就跳到下一方向
- 不读取仓库来出下一问
