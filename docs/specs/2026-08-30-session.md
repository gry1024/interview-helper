# 建会话、定方向与浅克隆设计文档

> 目标：用户提交 GitHub、项目陈述和岗位类别后，在不让代码参与出题的前提下，得到固定的 3～5 条面试方向和第一问；仓库浅克隆失败时仍能开始面试。

## 背景

当前已完成公网应用骨架和真实 JD/面经库，但“模拟面试”仍是静态说明页。第 2 步需要打通产品闭环的入口，并为后续逐轮 SSE 与代码核对 tool 建立可持久化会话。

本模块只实现建会话、开场定方向、浅克隆和开始页状态；不实现面中回答、代码检索、结束报告和复盘。

## 数据库改造

SQLite 文件：`data/app.db`。启动时参数化创建 `sessions` 表：

```sql
CREATE TABLE IF NOT EXISTS sessions (
    id TEXT PRIMARY KEY,
    created_at TEXT NOT NULL,
    github_url TEXT NOT NULL,
    statement TEXT NOT NULL,
    role TEXT NOT NULL,
    directions_json TEXT NOT NULL,
    current_direction_id TEXT NOT NULL,
    clone_path TEXT,
    clone_ok INTEGER NOT NULL DEFAULT 0 CHECK (clone_ok IN (0, 1)),
    status TEXT NOT NULL CHECK (status IN ('ready', 'live', 'ended')),
    first_question TEXT NOT NULL
)
```

- `id` 使用 UUID4；`created_at` 使用带时区 UTC ISO 字符串。
- `directions_json` 原样保存模型结构化结果，整场禁止改写。
- 新会话直接进入 `live`；`current_direction_id` 固定为第一条方向 id。
- clone 成功才保存 `clone_path`，否则为 `NULL` 且 `clone_ok=0`。
- SQLite 使用 `check_same_thread=False`；写入由进程内锁串行，所有值均使用占位符参数。

## API 设计

| 端点 | 方法 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| `/api/sessions` | POST | 匿名、按 IP 限流 | 校验输入，并行执行定方向与浅 clone，保存并返回会话 |

请求：

```json
{
  "github_url": "https://github.com/jingyaogong/minimind.git",
  "statement": "简历中的项目陈述",
  "role": "llm-algo"
}
```

响应：

```json
{
  "id": "uuid",
  "directions": [{"id": "d1", "title": "架构组件", "goal": "沿输入到输出解释核心组件"}],
  "first_question": "先从一个 token 进入模型后说起……",
  "clone_ok": true,
  "clone_error": null
}
```

错误：

- `422`：字段为空、超长、含控制字符、岗位不支持，或 URL 不是 `https://github.com/<owner>/<repo>[.git]`。
- `429`：同一 IP 60 秒内超过 10 次建会话请求。
- `502`：MiniMax 配置缺失、调用失败或结构化结果不合约；此时删除可能已产生的会话 clone，不落库。
- clone 超时、超限或 Git 错误不阻断面试，响应 `clone_ok=false` 并给出不含凭据的短错误。

## 并发与边界

1. 先生成 session id 和受控目标目录 `repos/{session_id}`。
2. 用 `asyncio.gather` 并行执行：
   - `git clone --depth 1 --single-branch --no-tags`；
   - MiniMax 开场定方向。
3. clone 只接受 HTTPS `github.com`，禁止 URL 凭据、端口、query、fragment 与额外路径。
4. clone 使用 `CLONE_TIMEOUT_SEC`；完成后计算目录普通文件总大小，超过 `CLONE_MAX_MB` 即删除并视为失败。
5. 提示词只包含岗位、项目陈述、`job_essence.md` 和真实面经问法；任何 clone 文件、文件名或行号都不进入定方向调用。
6. MiniMax 必须返回 3～5 条唯一方向，每条有 `id/title/goal`，第一问必须落在方向 1 的第一步。

## 前端设计

- “模拟面试”开始态展示 GitHub URL、项目陈述 textarea、岗位 select。
- 岗位值固定为 `llm-algo`（LLM 算法实习）、`training`（训练与对齐）、`rag`（RAG 与 Agent）。
- 点击“开始面试”后进入 loading，禁用表单并明确提示“正在确定方向并准备代码仓库”。
- 成功后同一主区切换为面试进行态：顶部打印全部方向 `title + goal`，其下显示第一问。
- clone 失败显示中性说明“代码仓库暂不可用，面试仍可继续”，不覆盖方向与首问。
- 失败使用 `.flash.error`，恢复按钮状态且不白屏。

## 安全考虑

- [x] 无登录，不采集额外身份信息。
- [x] URL 严格限定 `https://github.com`，禁止凭据和路径穿越。
- [x] 陈述最多 8000 字符、URL 最多 512 字符，全部文本拒绝控制字符。
- [x] 写接口按客户端 IP 每分钟最多 10 次。
- [x] 前端只用 `textContent` 渲染模型和用户文本。
- [x] clone 有超时、体积限制和会话目录边界。
- [x] MiniMax 密钥只从 `.env` 读取，日志与错误响应不回显密钥。

## 验收标准

- [ ] `pytest -q` 通过，非法 scheme/host/凭据/多余路径均被拒绝。
- [ ] curl 非 GitHub URL 返回 `422`，不创建 clone 目录。
- [ ] 使用 MiniMind 标准样本 POST 后返回 3～5 条方向，方向贴合架构组件、训练流水线或数据与指令。
- [ ] 第一问是方向 1 的具体第一步，不包含文件名或行号。
- [ ] 数据库方向与响应字节语义一致，`current_direction_id` 为首方向。
- [ ] 公网浏览器真实提交 MiniMind 标准样本后打印方向与首问。
- [ ] 公网浏览器另提交非法 URL，显示错误反馈而不是白屏。
- [ ] 375px 下表单可填写、提交结果可阅读。

## 实现顺序

1. 数据模型与 URL 校验。
2. SQLite 初始化及会话持久化。
3. 受限浅 clone。
4. MiniMax 封装与开场 Agent。
5. POST 路由、限流和错误映射。
6. 开始页表单、进行态与三种反馈状态。
7. 单测/curl → 提交推送 → 重启服务 → 公网浏览器实操。

## 反模式

- 不读取 clone 来生成方向或第一问。
- 不因 clone 失败而拒绝开始面试。
- 不提供假方向或离线 fallback 冒充 MiniMax 成功。
- 不在前端插入未经转义的 HTML。
- 不开始实现 SSE、code_inspect、报告或复盘。
