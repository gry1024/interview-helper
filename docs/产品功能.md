# 产品功能

左侧三个入口：**模拟面试** / **面试复盘** / **JD 库**。

产品形态是 **Agent**：系统提示 = 由 JD 库分析得到的岗位本质（技术骨干人设）；对话中可按需调用 **代码核对 tool**。

## 1. 模拟面试

### 开始前

用户提交：GitHub 链接、项目陈述、岗位类别。

并行准备：

- 读仓库，建立可被 tool 检索的项目事实。仓库全文不灌进面试官上下文。
- 按岗位加载 JD 库真实样本得出的 **岗位本质** 作为系统提示。不编造 JD。
- **定提问方向（不看仓库）**：根据项目陈述 + 岗位需求，模型想好几条大致方向，开场打印出来，作为整场 context。

然后开场提问。方向列表始终在场，不中途改写主线。

### 进行中：对话主界面 + 每答下方的思考

整屏只有问答。没有建议栏。

```
[左] 面试官提问
[右] 用户回答
     └─ 正下方：本轮思考（流式）
            · 如何评价这句
            · 是否 call 代码核对、查了什么、结论是什么
            · 本方向是否结束；继续引导下一步 / 进入下一条已定方向
     思考结束 → 下一问出现在左侧
```

思考只针对这一问一答。建议、岗位本质、总评不准出现在面中。

底部 **结束面试**。没有反问收尾。用户点结束才停。

### 下一问怎么出

开场前已定方向。面中不发明新主线。

1. 评价上一答好不好；必要时 call 代码核对（信不信、同方向往哪引）
2. **本方向没结束** → 只问这一条链路的下一步，把学生往下引。例：方向是 Transformer 原理，先问 attention：token 进来怎么编码、怎么进注意力；答完再引到输出侧。可以很多轮，Agent 必须锁在话题内。
3. **本方向已走完**（链路理完，或确认挖不动）→ 进入下一条已定方向。
4. 不问「Transformer 是怎样的」这种一锅端。

代码 **只** 用于：核对真伪、决定同方向怎么引。面中出题不引用文件名和行号。

### 点结束后

对话移到左侧；右侧生成综合报告（总评、岗位本质、知识建议、项目改良）。报告阶段 **仍可调用** 代码核对 tool，用于评估项目价值和改建议——这是代码另外两个合法用途。

本场全部原文写入复盘一条：每轮问答、每轮思考（含 tool 调用过程）、整份报告，不省略。

## 2. 面试复盘

点开一条 = 结束页原样（左对话右报告，两栏各自滚动）。展示不重写、不摘要、不重排。

## 3. JD 库

只展示网上搜集的真实 LLM 岗位：公司、岗位名、职责与要求、来源。禁止编造。

库的第二用途（不对用户生成）：离线分析 → **岗位本质** → Agent 系统提示。人设和议题权重只许引用库里已有条目。

## 4. 代码核对 Tool

面中思考、结束后报告都可启用。输入：当前 claim / 要查的点；输出：仓库里站不站得住、相关事实摘要（供决策，不直接念给学生当下一问）。

考察的是学生对项目底层的掌握：他说的，代码里有没有、是不是那么做的。
