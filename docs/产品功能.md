# 产品功能

左侧三个入口：**模拟面试** / **面试复盘** / **JD/面经 库**。

形态是两个 Agent：

- **面试官**：系统提示 = 真实 JD + 面经总结的岗位本质（大模型公司技术骨干）。可调：检索面经库、核对仓库、面经手撕。
- **老师**：另一套提示词。学生点「求助老师」时，只针对**当前这一问**给旁边小抄；不追问、不评分、不推进面试。需要对照实现时才调 `code_inspect`。学生仍须用自己的话回答面试官。

一场只面一个项目。

## 1. 模拟面试

### 输入

只要：**项目陈述**、**GitHub 仓库**、**岗位类别**（`llm-algo` / `training` / `rag`）。不解析整份简历。一次一个项目。

### 开始前

并行：

- 浅 clone 仓库，供 tool 检索。全文不灌进面试官上下文。
- 加载该岗位的 **岗位本质 / 骨干前置知识**（只来自库内真实 JD+面经）。
- **定话题方向（不看仓库）**：根据项目陈述 + 岗位需求想好几条方向，开场打印，贯穿全文，不中途改主线。

### 进行中

整屏只有对话。每条回答正下方打印思考，不给总评、不给建议。

```
[左] 面试官提问
[右] 用户回答
     └─ 正下方思考（流式）
            · 评价这句
            · 是否检索面经 / 核对仓库 / 打开手撕
            · 本话题继续挖 / 切换到下一条已定方向
     思考结束 → 下一问出现在左侧
```

思考只服务「把这个项目挖深」：继续还是换题、要不要对仓库、当前话题要不要按面经出手撕。挖到不能再挖为止。

底部：**发送**、**求助老师**、**结束面试**。用户点结束才停。求助不占一轮面试、不替学生交卷。

### 求助老师

面试进行中可点。老师 Agent 读最近对话和当前面试官那一问，给出短提示（须带「请用自己的话回答面试官」）。禁止预告后续方向、禁止把提示写成下一问。查仓库时不在提示里写文件名行号。

提示出现在对话里，与面试官气泡分开。次数写入本场记录；结束报告必须点名求助了几次、卡在哪一问。**不得因为小抄里有正确答案就把人抬成「真懂」。**

### 下一问

开场方向是宪法。面中不发明新主线。

1. 出下一问前检索面经库（改写原问，不对学生念「第 N 条」）
2. 必要时查仓库（信不信、同方向往哪引）
3. 必要时出手撕：当前话题属于面经常考实现（如 Transformer → MHA）则 call 编辑器；题只从面经题库取
4. 话题没结束 → 只引导链路下一步（可很多轮；答得差先换说法，不跳题）
5. 话题走完或换说法后仍挖不动 → 下一条已定方向
6. 口头提问不引用仓库文件名和行号，不劝用户点结束

仓库在面中用于核对与决定怎么引。手撕用于核实「会不会写」，不是另开刷题。

### 点结束后

对话左移；右侧综合报告——这里才出现：

- 总评
- 岗位本质（这类岗真正在筛什么，和你这个项目的距离）
- 知识掌握建议（哪一块还不够）
- 项目改良建议（成熟度、贴岗、前沿性上能改什么）

报告阶段仍可 call 代码核对：对照**代码事实 vs 求职者表述**。求助记录一并进入快照。

全文（每轮问答、每轮思考含 tool、老师提示、整份报告）原样写入复盘，一个字不省略。

## 2. 面试复盘

点开一条 = 结束页原样（左对话右报告，两栏各自滚动）。展示不重写。

## 3. JD 库（数据是产品的护城河）

页面同时展示两类网上真实样本，禁止编造。展示前会丢掉明确面向硕博、不含本科的条目；小红书来源排在前面。

- **JD**：公司、岗位、职责与要求、来源
- **面经**：公司、岗位、原文或可核对摘录、来源

**信息源**：小红书为主；兼各大招聘平台、模型公司官网。采集使用克隆的 [Spider_XHS](https://github.com/cv-cat/Spider_XHS.git) 做小红书侧，其它平台手工或同样可核对来源入库。

库的第二用途（不对用户现场生成）：离线总结 → 系统提示。JD 出筛人标准；面经出问法与追问习惯。人设和问法只许引用库里已有条目。这份数据决定我们和 ChatGPT、和市面通用面试助手的区分。

## 4. 面试官的三个 Tool（老师只用核对仓库）

**检索面经** `search_library`：仅面试官。出下一问前在已采集 JD/面经上做词面检索，优先改写库中原问。

**代码核对** `code_inspect`：面试官思考、老师求助、结束后报告都可启用。核表述与仓库是否一致。不把路径行号念给学生。

**手撕代码** `code_exercise`：仅面试官。聊到面经常考的实现时弹出编辑器。题只从 `code_exercises.json` 取。老师不调此 tool。报告阶段不调手撕与检索。

## 5. 刻意不做（功能边界）

产品只有三入口：模拟面试、面试复盘、JD/面经库。不在界面或 Agent 里做下列事项。


| 刻意不做         | 说明                         |
| ------------ | -------------------------- |
| 整份简历优化 / 解析  | 输入只有项目陈述 + 仓库 + 岗位类别       |
| 全岗位通用面试      | 人设只服务大模型相关岗；不做产品岗、泛技术岗模板   |
| 通用题库、笔试、八股   | 无独立刷题模块                    |
| LeetCode 式手撕 | 无链表排序背包；手撕只出面经题库里、贴当前话题的实现 |
| 多项目、实习经历、论文  | 一场一个项目；无论文链接、无实习拷问         |
| 语音 / 视频面试    | 纯打字                        |
| 登录 / 账号体系    | 匿名 session                 |
| 现场让模型编 JD    | 库内无来源的条目不准出现               |


量化等方向若要做，是新的知识库 + 新的人设，不是加一个「岗位下拉」复用当前面试官。
