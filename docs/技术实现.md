# 技术实现

README 只讲产品和怎么跑。本文写底层：进程、数据、Agent 循环、tool、前端如何对流。产品规格以根本文档 [PRODUCT_MEMO.md](../PRODUCT_MEMO.md) 为准，细则见 [产品理念.md](./产品理念.md)、[产品功能.md](./产品功能.md)。

---

## 1. 栈

| 层 | 实现 |
|---|---|
| 进程 | Python 3.10、FastAPI、uvicorn；`static/` 由 FastAPI 挂载 |
| 模型 | MiniMax，OpenAI SDK 指向兼容 Chat Completions；`temperature=0.2`，关闭 thinking（面中下一问必须秒级，不能等思考链） |
| 持久化 | SQLite `data/app.db`，写操作全局锁 |
| 仓库 | `git clone --depth 1` 到 `repos/{session_id}/`，仅 `https://github.com` |
| `GET /api/jds` | 本科向 JD/面经（过滤硕博定向，小红书优先排序） |
| `GET /api/health` | 探活 |
| 前端 | `static/index.html` + `app.js` + `styles.css`，无构建链 |

密钥只从环境变量读：`MINIMAX_API_KEY`、`MINIMAX_BASE_URL`、`MINIMAX_MODEL`。

## 2. 请求怎么走

```
浏览器 static/
    → POST /api/sessions          校验 URL、浅 clone、LLM 定方向（不看仓库）
    → POST /api/sessions/{id}/turns          SSE：思考 + 可选 tool + 下一问
    → POST /api/sessions/{id}/code-submissions  手撕提交，再走一轮 turn
    → POST /api/sessions/{id}/hints          老师 Agent：当前问小抄，不占 turn
    → POST /api/sessions/{id}/end            SSE：报告（含求助次数），落 reviews
    → GET  /api/jds                     本科向 JD/面经（滤硕博定向，小红书优先）
    → GET  /api/reviews / {id}          列表与 snapshot 原样回放
```

写接口按 IP 限流（窗口内约 10 次）。同一 session 同时只允许一轮 turn；求助走独立路由，不与 turn 抢同一条「推进面试」语义。无登录，session id 即身份。

核心文件：`app/main.py` 路由与 SSE；`app/agent.py` 定方向 / 一轮 / 报告；`app/teacher.py` 老师提示；`app/llm.py` 调 MiniMax 与 tool loop。

---

## 3. 为什么不是「把材料丢进模型」

系统提示拼的是 `job_essence.md` + 人设规则 + **本场已定方向**，不是整仓代码。

仓库进不了定方向那一轮。面中只有模型自己 `tool_calls` 时才跑本地函数，把短摘要塞回 messages 再让模型出思考和下问。所以问法仍像面试官，核对却有事实。

## 4. Agent 三回合

**开场 `plan_directions`**  
只喂项目陈述、岗位、岗位本质、相关 JD/面经摘录。输出 JSON：`directions`（3～5 条，含 title/goal）+ `first_question`（必须是 d1 的第一步）。clone 并行，失败不挡开面，`clone_ok=0` 时核对 tool 不可用。

**一轮 `run_turn`**  
带上方向列表、当前方向、对话史、上一答。模型可调：

| tool | 作用 | 硬约束 |
|---|---|---|
| `search_library` | 在 JD/面经库里搜原问，减少自己编 | 词面 BM25，返回带编号的摘录 |
| `code_inspect` | 在该场 clone 目录检索 | 根目录锁定、禁 `..`、跳过大文件/二进制、输出截断；禁止把路径行号写进下一问 |
| `code_exercise` | 打开面经手撕题 | 只从 `code_exercises.json` 解析；无匹配则报错，不生成题面 |

服务端对「吹 rerank / 万卡」等会补一次 inspect；聊到具体实现且题库能匹配时会补开手撕。每轮按当前话题检索面经并写入下一问的上下文，相关才返回、条数不固定。思考流式给前端，结束后再推 `question`。`direction_done` 为真才切到下一条已定方向，禁止新主线、禁止劝结束。

**结束 `write_report`**  
仍可 inspect。报告四段：总评、岗位匹配、知识建议、项目改良。`help_count > 0` 时必须写求助次数与卡在哪一问；老师提示不得把主档抬成「真懂」。然后把 session + turns + helps + 报告打进 `reviews.snapshot_json`，只插不改。

### 老师 Agent `write_teacher_hint`

独立于面试官。提示词 `prompts/teacher.md`。输入：最近对话 + 当前面试官那一问。只输出 `hint` + `looked_at_code`。可调的唯一 tool 是 `code_inspect`。提示禁止文件名行号，末尾要求学生用自己的话作答。落表 `helps`，复盘时插在对话时间线里，不是一条 `turns`。

LLM 封装：`complete_json` / `complete_json_with_tools`。tool 轮在服务端循环执行，再要终态 JSON。解析失败升 `LLMError`，不把密钥打进日志。

## 5. 表

- `sessions`：陈述、岗位、方向 JSON、当前方向、clone 路径与是否成功、`ready|live|ended`、首问
- `turns`：`interviewer` / `user` / `thought` 原文；thought 的 `meta_json` 记 tool 往返
- `reviews`：`report_text` + `snapshot_json`，一场一条
- `helps`：每次求助一条（当前问、hint 原文、是否查过代码）；结束快照只读拷贝，不改写

JD、面经、手撕题不进 SQLite，读 `app/jd/jds.json`、`interviews.json`、`code_exercises.json`。手撕题必须带 `source_ids` 指回样本。

## 6. SSE 事件

`POST .../turns` 与 `.../end` 为 `text/event-stream`：

| event | 含义 |
|---|---|
| `thought_delta` | 思考增量，前端打在**本条用户回答下方** |
| `tool` | 某次 tool 的 name / args / result |
| `code_exercise` | 打开编辑器：id、题面、starter（提交走独立路由，不锁对话） |
| `question` | 下一问 + `direction_id` + `direction_done` |
| `report_delta` | 结束报告增量 |
| `done` / `error` | 本轮结束或失败 |

前端 `static/app.js`：三入口切页；进行中单栏对话；结束后与复盘共用两栏渲染，数据只用 snapshot，不二次摘要。

---

## 7. 安全要点

- clone：仅 github.com HTTPS、无凭据、超时与体积上限、目录 `repos/{id}`
- inspect：session id 校验、路径规范化后必须落在 clone 根下
- 用户输入去控制字符、长度上限；SQL 参数化
- 思考/报告 Markdown 经 DOMPurify
- `.env` 与 `AGENT.md` 不进 Git

## 8. 采集

小红书侧 **借用** [cv-cat/Spider_XHS](https://github.com/cv-cat/Spider_XHS)（作者 [cv-cat](https://github.com/cv-cat)），**只作为离线数据获取工具**：把真实 JD/面经采进 `app/jd/`，不接入 FastAPI、不进入 Agent tool loop。招聘页与官网可手工入库。产品运行时 **不现场爬**。库的质量直接决定问法像不像骨干，这是和通用 Chat Completions 的分界。
