# interview-helper 详细开发计划

产品规格只认 [产品理念.md](./产品理念.md)、[产品功能.md](./产品功能.md)。**当前实现以代码与 [技术实现.md](./技术实现.md) 为准**；本文件是分步手册，冲突时改功能/技术文档，不把过期步骤当成运行时行为。

---

## 0. 一句话与闭环

低年级学生提交 GitHub + 项目陈述 + 岗位类别；Agent（系统提示 = 真实 JD/面经抽出的岗位本质）按开场定好的方向逐步深挖；代码是按需 tool；面中只展示思考，点结束后左对话右报告，全文原样进复盘。

砍到不能再砍的数据流：

```
提交 → 定方向并打印 → 问答循环（思考挂在该答下）→ 结束 → 报告 → 复盘原样回放
```

超过「把材料丢给 ChatGPT」靠三件：岗位本质进系统提示；开场定方向并锁话题引导；代码按需 tool，不灌进上下文。

## 4. 数据模型

建表放在 `app/db.py` 启动时 `CREATE TABLE IF NOT EXISTS`。全部参数化。

### sessions


| 列                    | 类型        | 含义                                     |
| -------------------- | --------- | -------------------------------------- |
| id                   | TEXT PK   | uuid                                   |
| created_at           | TEXT      | ISO                                    |
| github_url           | TEXT      | 用户提交                                   |
| statement            | TEXT      | 项目陈述                                   |
| role                 | TEXT      | 岗位类别，如 `llm-algo` / `rag` / `training` |
| directions_json      | TEXT      | `[{id, title, goal}]` 开场定死，整场不改        |
| current_direction_id | TEXT      | 当前锁着的方向                                |
| clone_path           | TEXT NULL | `repos/{id}`                           |
| clone_ok             | INTEGER   | 0/1                                    |
| status               | TEXT      | `ready` / `live` / `ended`             |
| first_question       | TEXT      | 开场第一问                                  |




### turns


| 列            | 类型         | 含义                                 |
| ------------ | ---------- | ---------------------------------- |
| id           | INTEGER PK | 自增                                 |
| session_id   | TEXT       |                                    |
| seq          | INTEGER    | 从 0；0 可表示系统展示方向 + 首问               |
| role         | TEXT       | `interviewer` / `user` / `thought` |
| body         | TEXT       | **原文，不摘要**                         |
| direction_id | TEXT NULL  | 该轮所属方向                             |
| meta_json    | TEXT NULL  | tool 调用记录：`[{name, args, result}]` |


一条用户回答对应：一条 `user`、一条 `thought`、随后一条 `interviewer`（下一问）。思考正文必须含：评价、是否查代码及结论、本方向是否结束。

### reviews


| 列             | 类型          | 含义                                                     |
| ------------- | ----------- | ------------------------------------------------------ |
| id            | TEXT PK     | 可与 session_id 相同                                       |
| session_id    | TEXT UNIQUE |                                                        |
| created_at    | TEXT        |                                                        |
| report_text   | TEXT        | 报告全文，不省略                                               |
| snapshot_json | TEXT        | 结束瞬间的完整副本：session 字段 + 全部 turns + report。复盘只读这份，禁止事后重写 |




### jds / 面经

不进 SQLite 也行，直接读 `app/jd/*.json`。每条字段：

```json
{
  "id": "bytedance-llm-intern-2026",
  "kind": "jd",
  "company": "字节跳动",
  "role": "大模型算法实习生",
  "source_url": "https://...",
  "source_name": "招聘官网 / 小红书 / 牛客",
  "text": "原文或可核对摘录",
  "captured_at": "2026-08-30"
}
```

面经 `kind: "interview"`，同样必须有 `source_url`。没有出处的条目不准入库。

## 5. API 契约

无登录。所有写接口限流（例如每 IP 每分钟 10 次 LLM 相关调用）。输入去控制字符，长度上限：陈述 8k、回答 8k、GitHub URL 512。

### `GET /api/jds`

返回 `{ "jds": [...], "interviews": [...] }`。服务端过滤明确面向硕博的条目，小红书来源排前。前端原样展示，禁止编造。

### `POST /api/sessions/{id}/hints`

老师 Agent。不占 turn。响应 `{ hint, looked_at_code, question }`。落 `helps`。

### `POST /api/sessions`

请求：

```json
{
  "github_url": "https://github.com/org/repo",
  "statement": "简历上的项目陈述",
  "role": "llm-algo"
}
```

服务端：

1. 校验 URL（只允许 github.com https）
2. 并行：浅 clone；加载 `job_essence.md` + 该 `role` 相关 JD/面经摘要进系统提示
3. **不把 clone 内容交给定方向的 LLM**。只喂：陈述、岗位、岗位本质、相关面经问法习惯
4. LLM 产出 3～5 条方向 + 第一条提问（落在方向 1 的第一步，禁止一锅端）
5. 落 `sessions`，方向打印给前端

响应：

```json
{
  "id": "...",
  "directions": [{"id": "d1", "title": "Transformer 原理", "goal": "从输入走到输出"}],
  "first_question": "先从注意力说起：一个 token 进来之后……",
  "clone_ok": true,
  "clone_error": null
}
```

clone 失败：`clone_ok=false`，面试仍开始；思考里写明代码 tool 不可用。

### `POST /api/sessions/{id}/turns`（SSE）

请求：`{ "answer": "..." }`。session 必须是 `live`/`ready`。

SSE 事件（`text/event-stream`），`data` 为 JSON：


| event           | data                                                               | 时机                        |
| --------------- | ------------------------------------------------------------------ | ------------------------- |
| `thought_delta` | `{ "text": "..." }`                                                | 思考流式                      |
| `tool`          | `{ "name": "code_inspect", "args": {}, "result": "..." }`          | 每次 tool 往返，原文进 thought 落库 |
| `question`      | `{ "text": "...", "direction_id": "d1", "direction_done": false }` | 思考结束后的下一问                 |
| `error`         | `{ "message": "..." }`                                             | 失败                        |
| `done`          | `{}`                                                               | 本轮结束                      |


前端：把 `thought_delta` 打在**刚才那条用户回答正下方**；`question` 出现在左侧新气泡。

服务端本轮必须：

1. 把用户回答落 `turns`
2. 带上：系统提示（岗位本质+人设）、方向列表、当前方向、对话史、上一答
3. 模型可决定是否 `code_inspect`
4. 输出结构化思考 + `direction_done` + `next_question`
5. 若 `direction_done`：`current_direction_id` 切到下一条已定方向；已是最后一条则下一问仍可在本方向收束，或提示「方向已走完，可结束」，**不发明新方向**
6. 落 `thought` + `interviewer` 原文



### `POST /api/sessions/{id}/end`（SSE）

无 body。事件：`report_delta` / `tool` / `done`。

服务端：再组一轮「报告」prompt，允许 `code_inspect`。报告必须含：总评、岗位本质对照、知识建议、项目改良。落 `reviews.snapshot_json` = session + 全部 turns（含本轮前所有思考）+ report 全文。`status=ended`。

### `GET /api/reviews`

`[{ id, created_at, statement_preview, role }]`

### `GET /api/reviews/{id}`

返回 `snapshot_json` **原样**。前端用与结束页同一套两栏组件渲染，禁止改写字段。

## 6. Agent 行为细则



### 6.1 系统提示拼装

顺序固定：

1. `interviewer.md`：你是 LLM 大厂技术骨干；短句；问本质；不问定义；不问文件行号；少 AI 味；负面清单（泛泛/横向/书本化/琐碎/不承接/外行）
2. `job_essence.md`：从真实 JD 归纳的筛人标准 + 从真实面经归纳的问法习惯。只许引用库内有的点
3. 本场：`role`、项目陈述、**已定方向列表**、当前方向 id
4. 明确：仓库不在上下文里；要核对就 call tool



### 6.2 开场定方向（不看代码）

要求模型输出 JSON：

```json
{
  "directions": [
    {"id": "d1", "title": "...", "goal": "这条链路要问到哪一步算走完"}
  ],
  "first_question": "..."
}
```

3～5 条。每条 `goal` 写清结束条件（例：把「输入→编码→attention→输出」问完）。`first_question` 必须是方向 1 的**第一步**，不能是「请介绍 Transformer」。

### 6.3 面中一轮

模型输出（可用 tool 后再输出）JSON + 给前端的思考自然语言：

```json
{
  "thought": "评价……\n查代码：是/否……\n本方向结束：是/否，因为……",
  "direction_done": false,
  "next_question": "……"
}
```

规则：

- `direction_done=false` → `next_question` 只能是本方向链路的下一步引导
- `direction_done=true` → `next_question` 必须是**下一条已定方向**的第一步（或已无下一条时的收束句，仍不新开方向）
- 答得差也不跳方向，除非 `goal` 已无法推进（学生明确不会且换说法仍空白，记为挖不动，才 `direction_done`）
- 同一方向允许多轮（Transformer 走完可能 8～15 轮）

实现上：先 stream 思考给前端，再发 `question`。若 SDK 不易同时 stream 又 tool，允许：tool 轮非流式，最终思考+问题再流；但思考必须在问题之前完整出现。

### 6.4 code_inspect

```
路径：app/tools/code_inspect.py
入参：query: str, path_hint: str | null
根目录：sessions.clone_path，禁止 `..`
行为：
  - 列顶层文件（截断）
  - 按文件名 / 关键词 grep（跳过 .git、node_modules、venv、>1MB 文件）
  - 命中则返回 路径 + 前后各 15 行，总输出 < 6k 字
返回：短摘要。供模型决策，禁止把路径行号写进 next_question
```

面中与报告共用。`clone_ok=0` 时 tool 返回「仓库不可用」。

### 6.5 结束报告

按 `report.md` 四段：总评（四档落差）、岗位本质对照、知识建议、最小改造。可 call tool。生成后不再改历史 turns。

## 7. 前端

单页，左侧固定三入口，主区切换。CSS 从设计系统复制变量。主标衬线，正文/输入无衬线。

### 7.1 壳

- 左栏：模拟面试 / 面试复盘 / JD 库（`tab-btn`，active 底边深炭）
- 不登录、无用户菜单



### 7.2 模拟面试 · 开始

表单：GitHub URL、项目陈述 textarea、岗位 select。主按钮「开始面试」（黑底白字）。提交后主区切到进行中；顶部或对话上方用细横线区分，**打印方向列表**（title + goal）。

### 7.3 模拟面试 · 进行中

整屏对话，无建议栏。

```
行：左气泡 = 面试官
行：右气泡 = 用户
      该右气泡正下方 = .thought（等宽/无衬线、次要色）流式填入
底部：输入框 + 发送；其旁「结束面试」（中性按钮，不是蓝）
```

思考结束前禁用发送。思考只渲染本轮评价/tool/是否换方向，过滤任何「建议你」「总评」类段落（后端也不该生成）。

### 7.4 模拟面试 · 已结束

布局改两栏：左 `overflow:auto` 对话（含全部 thought），右 `overflow:auto` 报告（markdown + DOMPurify）。中间 1px `var(--divider)`。与复盘详情共用组件 `renderEndedView(snapshot)`。

### 7.5 复盘

列表：`list-item`，时间 + 岗位 + 陈述前 40 字。点开调用同一 `renderEndedView`。两栏各自滚动。

### 7.6 JD 库

两组 `divider-section`：JD、面经。每条：公司、岗位、来源链接、原文。无来源不渲染。

### 7.7 三态

loading：spinner；空：empty-state；错：flash.error。桌面 >1024 三栏/两栏；<640 左入口改顶栏横滑，结束页两栏改上下堆叠且各滚。

## 8. 分步实现（必须按序，每步部署）

每步：改代码 → **单测/curl** → `git add` 具体文件 → commit → `git push` → 重启服务 → **AI 用浏览器工具打开公网，按第 10.1 节脚本实操**。单测绿了但浏览器没走通，本步不算完。第 3 步没跑通不准做美化和复盘花活。JD 先有真实样本即可，再补数量。

### 第 0 步 · 骨架与公网 hello

写：`requirements.txt`（fastapi, uvicorn, openai, python-dotenv）、`app/config.py`、`app/main.py`（`StaticFiles` + `GET /api/health`）、`static/*` 空壳三入口、`.env.example`、`AGENT.md`。

systemd 或：

```bash
uvicorn app.main:app --host 0.0.0.0 --port 80
```

验收：`http://120.26.176.60` 能开，三入口能切，health 返回 ok。安全组放行 80。

### 第 1 步 · JD / 面经库 + 岗位本质

`app/jd/jds.json`、`interviews.json`：能搜到多少是多少，宁缺毋假。来源优先招聘页、小红书、牛客、知乎。`GET /api/jds` + JD 库页。

`app/prompts/job_essence.md`：只根据已入库条目归纳筛人标准与问法习惯，每条主张能指回库内 id。

验收：页面每条能点到来源；无出处条目不存在。

### 第 2 步 · 建会话 + 定方向 + 浅 clone

先写 `docs/specs/2026-08-30-session.md`（表 + POST /sessions）。再写 `db.py`、clone、`agent.plan_directions`、开始页表单。

验收：用标准测试样本（MiniMind）提交后看到 3～5 条方向和第一问；方向应贴陈述（架构组件 / 训练流水线 / 数据与指令等），第一问没有文件名/行号。另开一场填非法 URL，确认错误提示。

### 第 3 步 · 一轮 SSE + 话题锁

先写 `docs/specs/2026-08-30-turn.md`。实现 `POST .../turns` 与前端气泡/思考对齐。`interviewer.md` 写死锁话题规则。

验收：MiniMind 场次中答完思考出现在该答下方，下一问在左；连续 3 答都在同一方向逐步推进（例如 RoPE 或 attention 链路），不会一答完跳题。

### 第 4 步 · code_inspect

实现 tool，挂进 turn 与（第 5 步）报告。思考区能看到 tool 事件。

验收：MiniMind 场次中声称「做了 rerank / 万卡分布式」时思考里出现检索结论；下一问仍不出现 `xxx.py:12`。

### 第 5 步 · 结束报告 + 落复盘

`POST .../end`、两栏布局、`snapshot_json`。

验收：建议/总评/岗位本质只在右侧；左栏对话与结束前一致；DB 里 turns.body 与报告全文无截断。

### 第 6 步 · 复盘回放

列表 + `renderEndedView(snapshot)`。验收：与结束页像素级同一结构，两栏各滚。

### 第 7 步 · UI checklist + 全站验收

对照设计系统第 8 节。走第 10 节清单。补 README（无密钥、无 IP 细节可放公开说明「自行配置 .env」）。

## 9. Prompt 与质量（追问是根本）

`interviewer.md` 必含：

- 人设：短、狠、问为什么/怎么证明，不夸
- 方向列表是全文宪法，禁止新主线
- 引导范例：方向=Transformer → 先问 token 进 attention，再编码，再输出，禁止「Transformer 是什么」
- 换说法再问一次的条件（虚、像背）
- 挖不动才结束方向
- tool 结果只影响评价和引导，不影响措辞暴露代码坐标

定方向与面中可各用一次 MiniMax；报告一次。不要用第二家模型「critic」。把 critic 规则写进同一 prompt 的自检段：发出前检查承接/下钻/有分量/像面试官。

## 10. 验证：单测 + 浏览器实操（强制）

两层都要，缺一不可。

| 层 | 干什么 | 证明什么 | 不够的时候 |
|---|---|---|---|
| 单测 / curl | `pytest` 测 clone 锁定、SQL、限流；curl 打 health / 建会话 / SSE 头 | 接口契约、回归 | 证明不了「思考是否贴在该回答下方」 |
| **浏览器实操** | AI **操控** Cursor 浏览器：打开公网、点、打字、提交、等流式、切页 | 真实用户路径 | 只截一张静态图 = 没验 |

实现者必须会用浏览器工具（`cursor-ide-browser`）：`browser_navigate` → `browser_lock` → `browser_snapshot` / 点击输入 → 必要时截图核对视觉 → 全程结束后 `unlock`。等页面变化用短轮询 snapshot，禁止干等。同一失败动作最多试 2 次，换假设再试。

公网基址：`http://120.26.176.60`（部署端口变了就改这里）。不要拿 localhost 截图冒充公网验收。

## 11. 安全与部署

- 密钥：`.env`，`pm2/systemd` 重启带上环境（若用 systemd，`EnvironmentFile=`）
- clone：仅 github.com；超时；目录锁死；禁止跟随到 `/`

- SQL：参数化
- 限流：防刷 token

- 提交截止前必须保持公网可访问；不要改 sshd 导致评委登不进

```bash
pytest -q

# 重启 uvicorn/systemd
```
