# 产品理念

## 宗旨

把简历上那个项目，变成你真正拥有的项目。

帮助求职者打磨这一个项目：更深地理解它、看清自己哪里还不够、项目质量差在哪、能改什么。只做这一件事。

## 给谁用

顶尖院校低年级本科生，投大模型相关岗位。

这类人同时踩三件事：

1. **实习经历不足** —— 低年级，简历上往往只有项目。
2. **项目成熟度不够** —— 竞赛、实验室科研居多，不一定匹配岗位，不一定跟得上前沿。
3. **自己不一定真懂这个项目** —— 代码可能是 AI 写的，底层认知不够。

面试官对这群人不考规模，只考「你是不是真的在思考」。所以产品不帮他们堆功能，只帮他们把已有的那一个项目真正据为己有。

## 市面为什么同质化、为什么不深

现有产品什么都有：模拟面试、笔试助手、题库、简历优化。功能全，没有一个核心有效。

- **简历优化**：收所有岗位、所有阶段，不够定制，不一定适合这个人这个岗。
- **题库 / 笔试 / LeetCode 刷题**：不是本质。链表排序背包去 LeetCode，不必做成通用刷题产品。本产品若出手撕，只出面经常考、且贴当前话题的实现（如 Transformer 话题下手写 MHA），题从面经题库取，不是另开一套刷题模块。
- **模拟面试**：根本在于面试官专不专业、追问质量高不高。这件事必须按岗位去定义。**市面做法是：一个通用于所有岗的预训练模型，塞一份简历和一段岗位上下文就开始问。要面大模型公司时，对面的人应该是懂训练、懂业务的技术骨干，而不是通用助手。** 不够差异化，也做不深，推不进某一类用户。

本产品刻意收窄：**只做大模型相关岗位的单项目深挖**。以后若做量化等方向，必须重新定制面试官——先采那个方向的 JD 和面经，再定义题型与人设。每个岗一套骨干，而不是一个适合所有人的通用面试。

## 怎么超过 ChatGPT 和通用面试助手

把 JD、项目陈述、代码链接丢进 ChatGPT，失败是结构性的：人设是空话、会讨好、不核对、问法像通用模型。

我们要 outperform 通用模型，打法是 **数据 + Agent 约束 + 按需工具**：

**数据是根本。** 区分性不来自更大的基座模型，来自别人没有的岗位知识库。从小红书、各大招聘平台、模型公司官网采集真实大模型 JD 和面经，离线总结成「岗位本质 + 面试官前置知识」，写入系统提示。面试官因此是 **大模型公司技术骨干**，不是套了角色扮演的通用 LLM。没有这层预设，问不出够专业的题。通用模型虽有预训练的海量数据，但一是注意力不够，二是面经时效性强，数据的实时性很重要。

**过程有约束。** 开场按项目陈述和岗位需求定方向并锁住；每答之后思考：继续本话题还是切换、要不要查仓库、当前话题若是面经常考实现则要不要打开手撕编辑器；出下一问前检索面经库。同一话题挖到不能再挖。

**按需工具。** `search_library` 改写库中原问。`code_inspect` 核仓库。`code_exercise` 核「会不会写」（题只从面经题库出）。真面试官看不见 GitHub，但大模型面经常当场手撕核心算子——这不是 LeetCode。

**仓库是镜子，不是出题卷。** 仍要 GitHub，是为了让求职者直面代码事实、少包装。问法不拿行号来问。

## 人设从哪来

两类真实样本，禁止编造：

- **JD**：企业写在纸上的筛人标准。
- **面经**：企业实际怎么面。信息源以小红书为主（新，质量高），兼招聘平台与公司官网。

JD 出「问什么能力」；面经出「怎么问、怎么追」。只有 JD 会像在念岗位说明书。

## 下一问怎么出

1. 开场前只根据项目陈述 + 岗位需求，预设若干话题方向（不看仓库），打印出来贯穿整场。一场只面这一个项目。
2. 每答之后：评价 → 检索面经 → 是否查仓库 → 是否按面经打开手撕 → 本话题继续引导，或切到下一条已定方向。不从空气里出题，不因一句答砸了就跳题。
3. 同一方向可以很多轮，一步步引到挖不动为止（例如 Transformer 从 attention 走到输出，而不是一问「它是什么」）。



## 测三种不够，给三类回馈


| 不够在哪                | 产品要让他看见                |
| ------------------- | ---------------------- |
| 理解不够（含 vibe coding） | 追问 + 查仓库 + 面经手撕：说得出，仓库对不对得上，核心实现写不写得出 |
| 讲不出来                | 懂但没有面试语言               |
| 项目本身弱 / 不贴岗 / 不够前沿  | 岗位本质对照 + 改良建议          |


结束后给出：总评、岗位本质、知识掌握建议、项目改良建议。目的不是打分，是让他知道改项目、补知识的方向。

面中另有 **老师 Agent**（不是面试官）：卡住时可求助，只给当前问的旁边小抄，不追问、不代答。结束时会计入求助次数，不能靠小抄把自己抬成「真懂」。

## 刻意不做（以及为什么）

只做：大模型岗位、单项目深挖、骨干人设来自真实 JD+面经、仓库按需核对、面经题库内的话题手撕。下面这些市面常做，我们明确不做。


| 刻意不做                    | 为什么                                         |
| ----------------------- | ------------------------------------------- |
| 整份简历优化                  | 收所有岗位、所有阶段，不够定制，不一定适合这个人这个岗                 |
| 整份简历解析                  | 一场只面一个项目；输入只收项目陈述，避免做成「万能简历工具」              |
| 全岗位通用面试官（产品岗、任意技术岗一套问法） | 面试官必须按岗位用 JD+面经定制。通用人设 = 预训练模型 + 简历，问不深、无差异 |
| 通用题库 / 笔试助手 / 八股        | 不是本质；题可以去别的网站搜                              |
| LeetCode 式刷题（链表、排序、背包）  | 与项目和岗位手撕无关；面经手撕只出当前话题的实现题                   |
| 多项目一起面、实习经历拷问           | 不一定有仓库，也稀释单项目深挖                             |
| 论文线、语音视频、登录注册           | 非本闭环；低年级主战场是项目                              |


以后若做量化等方向：不是把现有面试官「推广」过去，而是重新采该方向 JD 和面经，重新定制面试官。不做成适合所有求职者的大而全产品——那种已经烂大街，也推不进特定用户。
