# 产品理念

## 一句话

把简历上那个项目，变成你真正拥有的项目。

不测八股，不测刷题。只问：你真的熟这个项目吗？它对这个岗位有没有价值？

## 给谁用

低年级本科生，实习经历不足，找 LLM 算法实习时只能摊个人项目。面试官不考规模，只考「这个人是不是真的在思考」。

## 产品是一个 Agent，不是一次把材料喂给模型

把 JD、项目陈述、代码链接丢进 ChatGPT 让它追问，失败是结构性的：

- 材料一次性灌进上下文 → 它会按代码出题（真面试官做不到），或根本不核对（顺着你夸）
- 人设是一段「你是资深面试官」→ 问不出企业真正在筛的能力
- 没有强制流程 → 讨好、泛泛、横向跳、一轮放过
- 没有 critic → 问题专不专业全靠运气

我们要超过的就是这个基线。手段必须是 **Agent + 约束 + 按需工具**，不是更好的一段 prompt。

## 人设从哪来：海量真实 JD → 岗位本质 → 系统提示

面试官是 **LLM 大厂技术骨干**。这句话不能写在 prompt 里当装饰。

做法：JD 库只收网上真实 LLM 岗位样本（禁止编造）。对库做分析，抽出这类岗反复出现的筛人标准——数据、训练困难、评估是否可信、方法为什么这样选、能不能证明有效——写成 **岗位本质**，作为系统提示。

这样问出来的题才可能：够专业、贴企业、贴岗位、是面试官真在乎的能力。没有这层，开场定的提问方向会空、会外行。

## 代码是 Tool，不是上下文

GitHub **只**用于四件事：核对回答真伪、决定追问方向、最终评估项目价值、生成修改建议。不参与出题措辞，不引用文件名行号来提问。

代码核对做成 **可调用的 tool**。对话中面试官若觉得「这句必须先查代码再决定怎么问」，就 call 这个 tool 去看仓库；不需要查就不查。面中思考过程和结束后的报告都能调。

这同时在测学生对项目底层的掌握：他说的细节，仓库里站不站得住。

和 ChatGPT 的差别：ChatGPT 要么看见全部代码（问出不像人的题），要么看不见（无法识破）。Agent 是 **起疑才看**，问法仍是面试官的开放问题。

## 追问质量是产品根本

差追问的六种死法：泛泛、横向、书本化、琐碎、不承接、外行。一句外行，信任归零。

质量拆成四问，各自有实现，不押在模型临场发挥上：

| 要保证的 | 怎么实现 |
| --- | --- |
| 够专业 | 开场前定方向；同一方向内一步步引导，不一次甩「Transformer 是怎样的」 |
| 贴企业 | 岗位本质来自真实 JD 频次，不是想象中的大厂口味 |
| 贴岗位 | 提问方向只由项目陈述 + 岗位需求决定（不看仓库） |
| 面试官真在乎的能力 | 从 JD 抽出的筛人标准进系统提示；不问定义、不问代码行号、不问琐碎参数 |

下一问怎么出（取代「从有问题的 claim 里出题」）：

1. **开场前定方向，并打印出来，贯穿全文。** 正式开问前，模型根据项目陈述和岗位需求想好几条大致提问方向（例如：训练困难、评估是否可信、Transformer 原理）。不看仓库。开场就把这几条方向展示给用户，之后整场面试都以此为 context，不临场另起炉灶。
2. **面中只判两件事：这题答得好不好 → 本方向还没挖完就继续引导，挖完了再进下一条方向。** 不从空气里蹦题，也不因为一句答得差就跳题。
3. **同一方向要能走很多轮。** 方向是「问 Transformer」，不是一问「Transformer 是什么」。先从注意力切入：token 进来怎么编码、怎么进 attention；答完再引下一步，直到这条链路走完。Agent 必须判断「这个话题还没结束」，锁在话题内，结束才转向。

按需查代码只服务「这句信不信、同方向下一步往哪引」，不负责发明新方向。

## 测的是四种落差

同一点可换更朴素的说法再问一次：

| 档位 | 含义 | 处方（只在结束后报告里出现） |
| --- | --- | --- |
| 真懂 | 一问就稳 | 主推 |
| 懂但讲不出 | 换说法才答上 | 宿舍话译成面试话 |
| 真不懂 | 仍空白 | 从他自己仓库挖出答案 |
| 项目里没有 | 补课救不了 | 几小时内能做完的最小改造 |

## 面中看思考，面完才给处方

面中只摊开：怎么评价这句、有没有查仓库、为什么追问或换题。不给建议。用户点结束：对话左移，右侧出总评 / 岗位本质 / 建议。全文原样进复盘；点开复盘 = 结束页（两栏各自滚动），展示不重写。

## 刻意不做

八股、LeetCode、简历全文润色、多项目组合、论文线、实习经历拷问、语音、登录。只做项目深挖和诊断。
