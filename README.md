# interview-helper

**把简历上那个项目，变成你真正拥有的项目。**

---

## 理念

把简历上那个项目，变成你真正拥有的项目。帮助求职者打磨**一个**项目：更深地理解它、看清自己哪里还不够、项目质量欠缺在哪、能改什么。只做这一件事。

### 给谁用

经验丰富的求职者不会使用模拟面试产品。

我们的目标用户：985以上院校本科生，投大模型相关岗位。这类人可能能力很强，但经验少，年级低，conn不足：

1. **实习经历不足** —— 低年级，简历上往往只有项目。
2. **项目成熟度不够** —— 竞赛、实验室科研居多，不一定匹配岗位，不一定跟得上前沿。
3. **自己不一定真懂这个项目** —— 代码可能是 AI 写的，底层认知不够。

面试官对这群人重视的是你的真正能力边界，你的认知水平，即「你是不是真的在思考」。

### 产品理解

面试本质：合适的人 match 合适的岗位。模拟面试产品的根本价值在于给到高质量反馈。有效的反馈才能给到正确的梯度，由此更新我们的业务理解和表达能力，提高下次拿到 offer 的概率。

### 市面为什么同质化、为什么不深

我深度体验了市面上模拟面试相关的产品，发现功能一应俱全：模拟面试、笔试题库、简历优化，甚至实时作弊助手，都有。但所有的产品都同质化！

- **模拟面试**：根本在于面试官专不专业、追问质量高不高，必须按岗位去定义。**市面做法是：通用预训练模型 + 一份简历 + 一段岗位上下文。然而，真实面试中对方应该是懂训练、懂业务的技术骨干，而不是通用gpt。** 不够差异化，就做不深。
- **简历优化**：收所有岗位、所有阶段，全简历优化，看似面面俱到，但不够定制、深入，不一定适合这个领域，这个人，这个岗。
- **题库 / 笔试 / LeetCode 刷题**：不是面试本质。基础题去 LeetCode 等平台。本产品若出手撕，只出面经有记录、且贴当前话题的实现（如 Transformer 话题下手写 MHA），题从面经题库取。

本产品刻意收窄：**只做大模型相关岗位的单项目深挖**。全链路定制——先采领域 JD 和面经，再定义题型与面试官人设、工具。每个岗一套配置，而不是一个适合所有人的通用面试。

**用户调研**：本人以及采访身边本科生，经验资源connection不足，希望业界实习成长，但没有足够成熟项目，对业界理解不本质，难以找到第一份实习，只能在项目中成长打磨。

### 超越 ChatGPT 和市面上100%通用面试助手

把 JD、项目陈述、代码链接丢进 ChatGPT，失败是结构性的：人设是空话、会讨好、不核对、问法像通用模型、反馈不符合实际业务。

打法是 **数据 + Agent 约束 + 按需工具**：

- **数据是根本。** 区分性不来自更大的基座模型，来自实时更新的岗位知识库。从小红书、各大招聘平台、模型公司官网采集真实大模型 JD 和面经，总结成岗位本质与面试官前置知识，且在面试过程中随时检索。面试官因此是大模型公司技术骨干，不是套了角色扮演的通用 LLM。通用模型虽有海量预训练数据，但光靠prompt设定注意力不够，面经又强时效，预训练参数不含前沿insight。
- **过程有约束。** 开场按项目陈述和岗位需求定方向；每答之后思考：继续本话题还是切换、要不要查仓库、要不要按面经出手撕；出下一问前检索面经库改写原问；同一话题挖到不能再挖。
- **按需工具。** 1.检索面经库（问法贴真题）；2.核对仓库（表述 vs 代码事实）；3.话题内手撕（题只从面经题库出，提供代码编辑器）。

卡住时另有 **老师 Agent**（不是面试官）：只给当前问的旁边小抄，不追问、不代答。结束时会计入求助次数，不能靠小抄把自己抬成「真懂」。

面试官专业性来源：

- **JD**：企业写在纸上的筛人标准。「考察什么能力」
- **面经**：企业实际怎么面，求职者的经验分享。信息源以小红书为主，兼招聘平台与公司官网。「怎么问、怎么追」（小红书采集借用开源爬虫工具 [cv-cat/Spider_XHS](https://github.com/cv-cat/Spider_XHS)。）

### 功能模块

输入：**一个项目陈述 + GitHub 仓库 + 岗位**

1. 根据岗位选定面试官专家agent。开场前根据项目陈述预设若干话题方向，贯穿整场。一场只面这一个项目。
2. 每答之后：评价 → 检索面经/查仓库/考核手撕 → 判断本话题继续深挖，或切换方向提问。
3. 同一方向可以很多轮，一步步引到挖不动为止。

### 刻意不做

- **整份简历优化**：收所有岗位、所有阶段，不够定制
- **全岗位通用面试官**：必须按岗位用 JD+面经定制；通用人设问不深
- **通用题库 / 笔试 / 八股**：不是本质；基础题有大把优秀刷题平台
- **多项目一起面、实习经历拷问**：不一定有仓库，也稀释单项目深挖
- **论文线、语音视频、登录注册**：未来功能标配，初期不做。

根本文档见 [PRODUCT_MEMO.md](PRODUCT_MEMO.md)。同期维护见 [docs/产品理念.md](docs/产品理念.md)。

## 功能

产品只有三个入口。一场面试只收 **一个项目陈述 + GitHub 仓库 + 岗位**，不解析整份简历。


| 模块           | 做什么                                                                 |
| ------------ | ------------------------------------------------------------------- |
| **模拟面试**     | 开场定方向并锁住；每答后思考（继续/换题、查仓库、面经手撕）。可点「求助老师」拿当前问的小抄，不代答、不占一轮。点结束后左对话右报告。 |
| **面试复盘**     | 点开一条即结束页原样：左对话右报告，两栏各自滚动，原文不重写。                                     |
| **JD / 面经库** | 只展示有来源的真实样本，并离线总结进面试官系统提示+检索数据库。                                    |


面试官与老师是两套 Agent，都不是独立入口：

- **面试官**：检索面经库、核对仓库、按面经出手撕；口头提问不念文件名行号、不劝结束。
- **老师**：只给当前问的参考提示；需要时才查仓库；学生仍须自己回答面试官。结束报告会计入求助次数，不因小抄抬档。
- **面经手撕**：仅面试官可打开编辑器（如 Transformer 下手撕 MHA）；题只从面经题库取。

面中不给建议。总评与建议只出现在点「结束面试」之后的右侧报告里。

**刻意不做：** 整份简历优化、全岗位通用面试官、通用题库 / 笔试 / 八股、多项目一起面、实习经历拷问、论文线、语音视频、登录注册（未来功能标配，初期不做）。拓展岗位领域须从数据集 - 面试官定义 - 样本测试全链路定制一遍。

功能细则见 [docs/产品功能.md](docs/产品功能.md)。

## 本地复现

本仓库仅提供学习与复现用的代码，不含运行中的数据或凭证。

```bash
git clone https://github.com/gry1024/interview-helper
cd interview-helper
cp .env.example .env
```

编辑 `.env`，至少填入：`MINIMAX_API_KEY`、`MINIMAX_BASE_URL`、`MINIMAX_MODEL`（获取方式见 `.env.example` 内注释）。可选：`APP_HOST`、`APP_PORT`、`CLONE_TIMEOUT_SEC`、`CLONE_MAX_MB`。

```bash
python3 -m pip install -r requirements.txt
python3 -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

浏览器打开 `http://127.0.0.1:8000`。看到左侧三个入口（模拟面试 / 面试复盘 / JD/面经库）即启动成功。

建议用这一份样本走通主路径（岗位选 LLM 算法实习）：

- 仓库：`https://github.com/jingyaogong/minimind.git`
- 陈述：MiniMind 全链路轻量级大语言模型复现与训练（Tokenizer / 预训练 / SFT / DPO，RoPE、RMSNorm、SwiGLU）

```bash
pytest -q
```

单测不能代替在页面上真实点击。

## 安全设计

- 凭证只放 `.env`，已被 gitignore；不要把密钥、令牌、服务器密码写入仓库或本文
- GitHub 仓库白名单、clone 目录锁定，禁止路径逃逸
- SQL 参数化；思考与报告前端 XSS 过滤；写接口限流
- JD / 面经 / 手撕题均须可核对来源，禁止模型现场编造
